# SANDO 核心规划方法梳理与移植方案草稿

## 1. 研究目标

本文拟在现有 SANDO（Safe Autonomous Trajectory Planning for Dynamic Unknown Environments）系统基础上，提取其中与安全自主轨迹规划直接相关的核心算法，并将其适配到爱生比赛场景中。原 SANDO 系统包含完整的 ROS 2 通信、Gazebo 仿真、RViz 可视化、硬件接口、状态机、yaw 控制、悬停避障等工程模块。若直接整体迁移，系统复杂度较高，不利于算法理解、调试和论文验证。

因此，本文首先关注 SANDO 的核心规划闭环，即：

```text
地图表示与动态障碍预测
  → HGP 全局路径搜索
  → 安全走廊生成
  → Gurobi 局部轨迹优化
  → 在线重规划与轨迹拼接
```

研究目标可以概括为：

1. 梳理 SANDO 核心规划算法的完整数据流和计算流程；
2. 明确核心算法模块与非核心工程模块的边界；
3. 提取适用于比赛场景的最小规划闭环；
4. 在保证算法可验证性的前提下，弱化或暂时移除 yaw、RViz、Gazebo、硬件 TF 等工程细节；
5. 为后续论文方法章节、实验章节和工程实现提供统一技术框架。

在本文中，机器人被抽象为具有尺寸约束和动力学约束的移动体。规划器输入当前状态、目标点、环境地图以及动态障碍预测轨迹，输出一条满足安全约束和动力学约束的局部可执行轨迹。

---

## 2. 原 SANDO 系统流程

原 SANDO 系统是一个周期性在线重规划系统，而不是一次性规划系统。其核心执行逻辑可以描述为：系统持续接收机器人状态、目标点、点云地图和动态障碍轨迹；定时触发重规划；每次重规划在当前局部地图窗口内搜索粗路径，并基于该路径生成安全走廊和局部多项式轨迹；最后将新轨迹拼接到当前正在执行的轨迹序列中。

整体流程如下：

```text
ROS 输入
  ├─ 机器人状态 state
  ├─ 终端目标 G_term
  ├─ 已知占据点云 / 未知空间点云
  └─ 动态障碍预测轨迹
        ↓
SANDO::replan()
        ↓
findAandAtime()
  从旧轨迹 plan_ 中选取未来接轨点 A
        ↓
computeG()
  根据终端目标和规划视野生成局部目标 G
        ↓
updateMap()
  点云地图与动态障碍信息更新为局部体素地图
        ↓
generateGlobalPath()
  HGP 在体素地图中搜索 A 到 G 的粗路径 global_path
        ↓
findSafeSubGoal()
  遇到未知空间时截断粗路径
        ↓
planLocalTrajectory()
  沿 global_path 生成安全走廊并优化局部轨迹
        ↓
appendToPlan()
  将新轨迹拼接到当前执行轨迹 plan_
        ↓
publishGoal()
  持续发布下一时刻轨迹跟踪目标
```

其中，`G_term` 表示最终目标点，`A` 表示本次重规划的起点，`G` 表示当前规划视野内的局部目标，`global_path` 表示 HGP 输出的离散粗路径，`plan_` 表示当前正在执行的轨迹点序列。

原系统中，全局规划与局部规划并不是前后独立的一次性流程，而是在每次重规划中共同执行：

```text
重规划 replan()
  ├─ 全局路径搜索 generateGlobalPath()
  └─ 局部轨迹优化 planLocalTrajectory()
```

因此，全局规划、局部规划和重规划之间的关系为：

- 重规划是系统的外层在线循环；
- 全局规划为局部轨迹优化提供几何引导路径；
- 局部规划将几何路径转换为满足安全约束和动力学约束的连续轨迹。

## 3. 核心算法模块

### 3.1 HGP 全局路径搜索

HGP（Hierarchical/Heuristic Global Planner）模块负责在体素占据地图上搜索一条从本次重规划起点 `A` 到局部目标 `G` 的粗路径。该路径并不是最终可执行轨迹，而是局部轨迹优化的几何引导。

#### 3.1.1 局部目标生成

在每次重规划中，系统首先根据当前接轨点 `A` 和终端目标 `G_term` 生成局部目标 `G`。若终端目标距离较远，则 `G` 是 `G_term` 在当前规划视野半径 `horizon` 内的投影点。可表示为：

```math
G = A + h \frac{G_{\mathrm{term}} - A}{\|G_{\mathrm{term}} - A\|}
```

其中，`h` 为规划视野半径。当终端目标位于视野范围内时，局部目标可直接取为终端目标。

该步骤的作用是将长距离目标转化为当前局部地图范围内的可规划目标，从而使在线重规划始终在有限局部窗口中运行。

#### 3.1.2 体素地图表示

原系统通过点云输入构建局部体素地图。根据不同运行场景，地图输入可能包括：

- 已知占据点云；
- 未知空间点云；
- 动态障碍当前位置与预测轨迹；
- 地图边界与高度约束。

点云数据被离散化为体素栅格。每个体素可表示为：

```math
m(i,j,k) \in \{\mathrm{free}, \mathrm{occupied}, \mathrm{unknown}\}
```

HGP 在该离散地图中进行路径搜索。对真实或半真实感知场景，未知区域通常被视为不可安全穿越区域；对简化仿真场景，可仅使用占据点云构建地图。

#### 3.1.3 搜索目标

HGP 输出一条离散折线路径：

```math
\mathcal{P}_{g} = \{p_0, p_1, \ldots, p_M\}
```

其中：

```math
p_0 = A,\quad p_M \approx G
```

该路径用于表示从当前接轨点到局部目标的可通行拓扑方向。HGP 可通过 A*、JPS 或带动态障碍热力代价的 A* 搜索实现。其代价函数可抽象为：

```math
J_{\mathrm{HGP}} = J_{\mathrm{dist}} + \lambda_u J_{\mathrm{unknown}} + \lambda_h J_{\mathrm{heat}}
```

其中：

- `J_dist` 表示路径长度或网格移动代价；
- `J_unknown` 表示未知区域代价；
- `J_heat` 表示动态障碍预测轨迹附近的软代价；
- `lambda_u` 和 `lambda_h` 为权重系数。

因此，HGP 并非只避开静态障碍物。它在体素地图层面可以同时考虑静态占据、未知空间、动态障碍当前占据以及动态热力图代价。

#### 3.1.4 粗路径的作用

HGP 输出的 `global_path` 具有如下特点：

1. 是离散几何路径，而不是可执行轨迹；
2. 可以指示从障碍物左侧或右侧绕行等拓扑选择；
3. 不保证速度、加速度、jerk 等动力学约束；
4. 不保证轨迹平滑性；
5. 需要进一步生成安全走廊并进行连续轨迹优化。

因此，HGP 的主要作用是为局部轨迹优化提供几何引导，而不是直接控制机器人运动。

### 3.2 安全走廊生成

安全走廊生成模块负责沿 HGP 输出的粗路径构造一组无碰撞凸多面体，使后续轨迹优化可以在凸约束内进行。安全走廊是连接离散搜索路径与连续轨迹优化的关键中间表示。

#### 3.2.1 凸多面体表示

每个安全走廊多面体可表示为线性不等式约束：

```math
\mathcal{C}_i = \{x \in \mathbb{R}^3 \mid A_i x \le b_i\}
```

其中，`A_i` 和 `b_i` 表示第 `i` 个多面体的半空间约束。

若 HGP 粗路径为：

```math
\mathcal{P}_{g} = \{p_0, p_1, \ldots, p_M\}
```

则路径段：

```math
[p_i, p_{i+1}]
```

可对应生成一个安全多面体：

```math
\mathcal{C}_i
```

使该多面体尽可能包围路径段附近的自由空间，同时排除静态障碍、未知空间和动态障碍可能占据区域。

#### 3.2.2 静态环境下的空间安全走廊

在静态环境假设下，障碍物不随时间变化。此时可以沿粗路径生成一组空间安全走廊：

```math
\mathcal{C} = \{\mathcal{C}_0, \mathcal{C}_1, \ldots, \mathcal{C}_{M-1}\}
```

轨迹优化时要求轨迹控制点或轨迹片段落在对应安全多面体内，从而保证轨迹不与障碍物发生碰撞。

#### 3.2.3 动态环境下的时空安全走廊

在动态环境中，障碍物位置随时间变化。若仅生成一套空间安全走廊，则无法准确表达“机器人在不同时间经过同一空间区域时的安全性差异”。因此，SANDO 引入时间分层安全走廊。

假设局部轨迹被划分为 `N` 个时间段，HGP 路径被划分为 `P` 个空间段，则时空安全走廊可表示为：

```math
\mathcal{C}_{n,p}, \quad n=0,\ldots,N-1,\quad p=0,\ldots,P-1
```

其中，`n` 表示时间层，`p` 表示空间路径段。每个时间层对应不同的动态障碍物预测位置或膨胀范围。

若第 `n` 个时间层结束时刻为：

```math
t_n = (n+1)\Delta t
```

则动态障碍物可根据预测轨迹或最大速度在该时间层进行膨胀。简化情况下，可采用：

```math
r_{\mathrm{dyn}}(t_n) = r_0 + v_{\max}^{\mathrm{obs}} t_n
```

其中，`r_0` 为障碍物初始包围盒或安全半径，`v_max^obs` 为动态障碍物最大速度。

#### 3.2.4 最坏情况动态膨胀

系统中还包含 `dynamic_worst_case` 模式。该模式不构造完整的时间分层走廊，而是将所有空间段的动态障碍物统一按照最大轨迹时间进行膨胀：

```math
T_{\max} = N \Delta t_{\max}
```

并令每个空间段的动态障碍物膨胀时间均为 `T_max`。这种方法计算简单，但较为保守。它适合作为对照实验，用于比较时空安全走廊相对于最坏情况膨胀的优势。

#### 3.2.5 安全约束的含义

本文中的安全约束主要指轨迹必须位于安全走廊内部：

```math
A_i x(t) \le b_i
```

或在时间分层情况下：

```math
A_{n,p} x(t) \le b_{n,p}
```

该约束间接保证轨迹避开：

1. 已知静态障碍物；
2. 未知空间；
3. 膨胀后的动态障碍物；
4. 机器人自身尺寸造成的碰撞风险；
5. 地图边界与高度限制。

### 3.3 Gurobi 局部轨迹优化

在获得安全走廊后，系统使用 Gurobi 求解一条满足安全约束和动力学约束的局部连续轨迹。该轨迹通常表示为分段多项式或样条形式。

#### 3.3.1 轨迹表示

局部轨迹可表示为：

```math
x(t) =
\begin{cases}
x_0(t), & t \in [t_0, t_1] \\
x_1(t), & t \in [t_1, t_2] \\
\cdots \\
x_{N-1}(t), & t \in [t_{N-1}, t_N]
\end{cases}
```

其中，`N` 为轨迹时间段数。每段轨迹由多项式控制点或系数表示。代码中使用 MINVO/Bezier/B-spline 相关基变换，以便将轨迹约束转化为控制点约束。

#### 3.3.2 初末状态约束

局部轨迹优化从接轨点 `A` 开始，到局部终点 `E` 结束：

```math
x(t_0) = x_A,\quad \dot{x}(t_0) = v_A,\quad \ddot{x}(t_0)=a_A
```

```math
x(t_N) = x_E
```

根据状态不同，终点约束可以更强或更弱。例如接近目标时，系统更倾向于使轨迹末端严格到达局部目标；正常飞行中，则通常以 HGP 粗路径末端作为局部轨迹终点。

#### 3.3.3 动力学约束

轨迹必须满足机器人动力学限制，包括速度、加速度和 jerk 约束：

```math
\|\dot{x}(t)\| \le v_{\max}
```

```math
\|\ddot{x}(t)\| \le a_{\max}
```

```math
\|\dddot{x}(t)\| \le j_{\max}
```

实际代码中可选择不同范数形式，如 `Linf`、`L1` 或 `L2` 约束。其中 `Linf` 约束可写为：

```math
|\dot{x}_k(t)| \le v_{\max},\quad k \in \{x,y,z\}
```

加速度和 jerk 约束同理。

#### 3.3.4 安全走廊约束

若轨迹控制点位于凸多面体内，则可保证对应轨迹段位于安全走廊内。对于第 `i` 个多面体，约束形式为：

```math
A_i q_{i,j} \le b_i
```

其中，`q_{i,j}` 表示轨迹段的控制点。

在时间分层安全走廊中，约束进一步变为：

```math
A_{n,p} q_{n,j} \le b_{n,p}
```

表示第 `n` 个时间段的轨迹控制点必须落在相应时间层和空间段的安全多面体中。

#### 3.3.5 优化目标

SANDO 的局部优化目标主要倾向于生成平滑轨迹。可抽象表示为最小化 jerk：

```math
\min \int_{t_0}^{t_N} \|\dddot{x}(t)\|^2 dt
```

在实际实现中，该目标被离散化并转化为 Gurobi 可处理的二次优化目标，同时加入安全走廊、动力学和地图边界约束。

#### 3.3.6 多时间因子并行求解

局部轨迹优化中引入时间放大系数 `factor`。若基础时间步长为 `initial_dt`，则实际每段轨迹时间为：

```math
\Delta t = \mathrm{factor} \cdot \Delta t_0
```

较小的 `factor` 对应更快轨迹，但优化更难可行；较大的 `factor` 对应更慢轨迹，但更容易满足安全和动力学约束。

系统并行尝试多个 `factor`：

```text
factor_1, factor_2, ..., factor_K
```

每个 `factor` 对应一个 Gurobi solver。谁先求得可行轨迹，系统即采用其结果，并请求其他 solver 停止。这一机制提高了在线重规划实时性。

### 3.4 动态障碍预测与时空约束

动态障碍处理是 SANDO 区别于静态轨迹规划方法的重要部分。系统需要预测动态障碍物在未来时间内的位置，并在全局路径搜索和局部轨迹优化中体现其影响。

#### 3.4.1 动态障碍轨迹表示

每个动态障碍物可表示为一条时间参数化轨迹：

```math
o_k(t)
```

其中，`k` 表示障碍物编号。障碍物还具有包围盒尺寸：

```math
b_k = [b_x, b_y, b_z]^T
```

为了考虑机器人自身尺寸，障碍物包围盒通常需要与机器人包围盒合并，得到膨胀后的碰撞检测区域：

```math
b_k^{\mathrm{safe}} = \frac{1}{2}b_k^{\mathrm{obs}} + \frac{1}{2}b^{\mathrm{robot}}
```

该处理等价于将有尺寸机器人的避障问题转化为点机器人避开膨胀障碍物的问题。

#### 3.4.2 动态障碍预测来源

原系统中，动态障碍预测主要由 obstacle tracker 节点完成。其流程为：

```text
点云输入
  → 欧式聚类
  → 障碍物中心与包围盒估计
  → EKF / adaptive EKF 跟踪位置、速度和加速度
  → 生成未来轨迹 DynTraj
  → 发布 predicted_trajs
```

在核心算法移植初期，可不完整迁移点云聚类和 EKF 模块，而采用简化预测模型，例如给定障碍物初始位置、速度和尺寸，构造匀速或匀加速预测轨迹：

```math
o_k(t) = o_k(0) + v_k t
```

或：

```math
o_k(t) = o_k(0) + v_k t + \frac{1}{2}a_k t^2
```

这样可以先验证规划器对动态障碍预测的利用能力，再逐步加入真实感知预测模块。

#### 3.4.3 动态热力图代价

在 HGP 搜索阶段，动态障碍物不仅可以作为硬占据区域，也可以通过热力图形式作为软代价影响路径选择。动态障碍物预测轨迹附近的体素会获得更高代价，使 HGP 倾向于避开未来潜在冲突区域。

可抽象表示为：

```math
J_{\mathrm{heat}}(x,t) = \sum_k \phi(\|x - o_k(t)\|)
```

其中，`\phi(\cdot)` 为随距离衰减的代价函数。

#### 3.4.4 时空安全约束

在局部轨迹优化阶段，动态障碍物主要通过时空安全走廊体现。对于轨迹第 `n` 个时间段，系统根据对应时间层内动态障碍物的位置或膨胀范围生成安全多面体：

```math
\mathcal{C}_{n,p}
```

并要求轨迹控制点满足：

```math
q_{n,j} \in \mathcal{C}_{n,p}
```

这使得轨迹不仅在空间上避障，而且在时间上避开动态障碍物可能占据区域。

### 3.5 在线重规划

在线重规划是 SANDO 系统的外层运行机制。系统并非一次性生成完整路径，而是随着机器人运动、地图更新和动态障碍变化不断重新规划。

#### 3.5.1 未来接轨点 A 的选择

若每次重规划都从机器人当前状态开始，则由于规划计算存在耗时，轨迹生成完成时机器人已经离开当前状态，导致新轨迹难以平滑接入。因此，SANDO 从当前正在执行的轨迹 `plan_` 中选取一个未来点作为新轨迹起点 `A`。

设当前轨迹点序列为：

```math
\mathcal{Q} = \{q_0, q_1, \ldots, q_L\}
```

系统选择：

```math
A = q_{L-k}
```

其中，`k` 由规划计算耗时自适应调整。若规划耗时较长，则选择更远的未来点，以保证新轨迹计算完成时机器人接近该接轨点。

#### 3.5.2 轨迹拼接

局部优化得到的新轨迹离散点为：

```math
\mathcal{Q}_{new} = \{\hat{q}_0, \hat{q}_1, \ldots, \hat{q}_N\}
```

系统将旧轨迹中接轨点之后的部分替换为新轨迹：

```text
旧 plan_ 前半段保留
接轨点之后拼接新轨迹
```

该机制保证了在线重规划过程中的轨迹连续性。

#### 3.5.3 重规划触发条件

重规划需要满足：

1. 已获得当前机器人状态；
2. 已获得终端目标；
3. 地图已经初始化；
4. 未到达终点或存在悬停避障需求；
5. 当前轨迹仍需要更新。

此外，到达目标并不仅仅由位置距离判断，还需要考虑速度是否足够小。其原因是机器人可能高速掠过目标点，若仅以距离作为判断条件，可能误判为已到达。

#### 3.5.4 最小重规划闭环

为适配比赛场景，本文建议首先提取最小在线重规划闭环：

```text
输入：
  当前状态
  目标点
  静态地图
  动态障碍预测轨迹

过程：
  选取接轨点 A
  计算局部目标 G
  更新局部地图
  HGP 搜索粗路径
  生成安全走廊
  Gurobi 优化局部轨迹
  拼接轨迹

输出：
  可执行轨迹点序列
```

该闭环保留 SANDO 的核心规划思想，同时避免过早引入完整 ROS/Gazebo/硬件控制系统带来的工程复杂性。

## 4. 非核心工程模块

原 SANDO 系统中还包含大量工程模块。这些模块对于完整无人机系统运行非常重要，但并非验证核心规划算法所必需。在算法移植初期，可对这些模块进行弱化或延后处理。

### 4.1 yaw 控制

原系统根据无人机状态计算 yaw 和 yaw rate。例如：

- `YAWING`：刚收到目标时先朝向目标方向；
- `TRAVELING`：飞行中 yaw 朝速度方向；
- `GOAL_SEEN`：接近目标时继续平滑调整 yaw；
- `GOAL_REACHED`：到达后保持上一帧 yaw；
- `HOVER_AVOIDING`：悬停避障时朝向悬停点。

yaw 控制对于真实无人机飞行很重要，但在核心算法验证阶段，可以先忽略或简化为：

```math
\psi = \mathrm{atan2}(\dot{y}, \dot{x})
```

即令机体朝向速度方向。

### 4.2 hover avoidance

悬停避障用于处理机器人到达目标后，动态障碍物靠近悬停点的情况。该模块属于安全保护逻辑，而不是核心轨迹优化方法本身。

在算法提取初期，可先不考虑该模块。动态避障重点放在飞行过程中的时空安全走廊和在线重规划。

### 4.3 RViz 可视化

RViz 用于显示：

- HGP 粗路径；
- 安全走廊；
- 局部轨迹；
- 动态障碍物；
- heat map；
- 当前状态与目标点。

可视化对调试非常有价值，但不应与核心算法强耦合。移植时建议保留最小可视化接口，例如输出 `global_path`、`polytope` 和 `trajectory`，而不直接迁移原系统所有 marker 发布函数。

### 4.4 Gazebo 仿真

Gazebo 提供机器人模型、传感器模拟、动态障碍物环境和物理仿真。但完整接入 Gazebo 会引入：

- URDF 模型；
- 传感器插件；
- TF 坐标变换；
- topic remap；
- 仿真时间；
- 动态障碍物模型。

因此，建议在算法移植初期不直接依赖 Gazebo，而是通过静态点云地图和手动构造的动态障碍物轨迹验证核心规划闭环。待核心算法跑通后，再接入 Gazebo 或比赛仿真环境。

### 4.5 hardware TF

硬件 TF、Vicon、里程计转换、初始位姿变换等模块用于真实无人机实验。在比赛场景适配初期，若比赛平台已提供统一坐标系下的机器人状态，则无需迁移完整硬件 TF 逻辑。

该部分可抽象为：

```text
比赛平台状态接口
  → RobotState
```

只要保证输入状态位于规划器使用的坐标系中，即可暂时绕开原系统复杂的硬件坐标变换逻辑。

## 5. 小结

综上，SANDO 的核心方法可以概括为：

```text
在局部体素地图中利用 HGP 搜索几何粗路径，
沿粗路径生成空间或时空安全走廊，
再通过 Gurobi 优化生成满足安全约束与动力学约束的分段多项式轨迹，
并通过在线重规划机制持续更新轨迹。
```

对于爱生比赛场景，本文建议首先提取如下核心：

```text
SANDO-Core = HGP 全局路径搜索
           + 安全走廊生成
           + Gurobi 局部轨迹优化
           + 简化动态障碍预测
           + 最小在线重规划
```

暂时弱化或延后：

```text
yaw 状态机
hover avoidance
完整 RViz marker
Gazebo 仿真插件
硬件 TF / Vicon 接口
完整 obstacle tracker
```

这样可以在保持研究纯度的同时，先验证 SANDO 核心规划算法在比赛场景中的有效性，再逐步补充工程系统能力。
